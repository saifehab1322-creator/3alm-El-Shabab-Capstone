# 3ALM ELSHABAB — منصة حجز ملاعب سوهاج

## هل المشروع كان يحتاج خادمًا؟ (توضيح مهم)
نعم. النسخة السابقة كانت HTML/CSS/JS فقط وتحفظ الحسابات والحجوزات في `localStorage` داخل متصفح كل مستخدم؛ وأي تحقق من «كود تفعيل» في هذه الحالة يمكن تخطيه بفتح أدوات المتصفح، فلا يصلح لحماية تسجيل أصحاب الملاعب.
لذلك أُضيف **خادم Node.js + قاعدة بيانات SQLite**، وانتقلت إليهما الحسابات والحجوزات والملاعب والرسائل. **التحقق من الكود والصلاحيات يتم على الخادم فقط.**
بيانات `localStorage` القديمة (تجريبية) لا تُنقل تلقائيًا.

## المتطلبات والتشغيل
- Node.js **22.13 أو أحدث** (لا يوجد `npm install`؛ الخادم لا يعتمد على أي حزم خارجية: يستخدم `node:sqlite` و`crypto` المدمجين).
```
cd 3alm-elshabab
npm start            # أو: node --no-warnings server/server.js
```
افتح http://localhost:3000 (لا يعمل بفتح الملفات مباشرة `file://`).

عند **أول تشغيل** يُنشأ حساب المسؤول `admin@3almelshabab.com` وتُطبع كلمة مروره العشوائية **مرة واحدة** في الطرفية (احفظها). أو حدّدها بنفسك:
`ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='Str0ngPass' npm start` (يُستخدم فقط إن لم يوجد مسؤول). لا توجد كلمات مرور أو أكواد داخل ملفات HTML/JS.

| متغير بيئة | الافتراضي | الوظيفة |
|---|---|---|
| `PORT` | 3000 | منفذ الخادم |
| `DATA_DIR` | `server/data` | مكان قاعدة البيانات `app.db` والصور المرفوعة `uploads/` (**خذ منه نسخة احتياطية**) |
| `COOKIE_SECURE` | — | ضع `1` عند التشغيل خلف HTTPS ليصبح كوكي الجلسة `Secure` |
| `TRUST_PROXY` | — | ضع `1` خلف Nginx/Cloudflare ليُقرأ IP الزائر من `X-Forwarded-For` (لتحديد المحاولات) |

## سير العمل: أكواد أصحاب الملاعب
1. صاحب الملعب يتواصل معك (صفحة «تواصل») وتتحقق من بياناته خارج الموقع.
2. من **لوحة التحكم ← أكواد أصحاب الملاعب** أنشئ كودًا (اسم/ملاحظة تحقق + مدة صلاحية 1–90 يومًا). يظهر الكود **كاملًا مرة واحدة فقط** لتسلّمه له؛ بعدها يُعرض مقنّعًا (`OWN-••••-••••-XXXX`).
3. صاحب الملعب يسجّل من `owner-register.html` ببياناته وبيانات ملعبه والكود. يُتحقق على الخادم من: وجود الكود، عدم استخدامه، عدم إلغائه، وعدم انتهائه. عند النجاح يُنشأ الحساب (دور `owner`) وملعبه (غير منشور) ويُربط الكود بالحساب ويُقفل في **نفس العملية الذرية**، فلا يمكن استخدامه مرتين حتى مع طلبات متزامنة.
4. يدخل من `owner-login.html` إلى **لوحة صاحب الملعب**: بيانات الملعب، السعر، مواعيد العمل، الصور (تظهر كلها للزوار في معرض صور)، نشر/إخفاء الملعب، ومتابعة حجوزات ملاعبه.
   - **إغلاق فترات معيّنة** (صيانة / حجز خاص / إجازة / يوم كامل): تظهر للزوار كمواعيد غير متاحة ويرفضها الخادم عند الحجز. لا يمكن إغلاق فترة بها حجز مؤكد.
   - **إلغاء حجز على ملعبه** مع سبب اختياري يظهر للعميل في «حجوزاتي».
5. المسؤول يستطيع: إلغاء كود غير مستخدم، إنشاء كود بديل، رؤية الأكواد المستخدمة وحسابات أصحابها، وبيانات أصحاب الملاعب، و**إيقاف/تفعيل أي حساب** (يُسجَّل خروجه فورًا وتُخفى ملاعبه عن الجمهور)، و**تعديل بيانات أي ملعب وحذف صوره**.
6. الملعب الجديد بلا تقييم يظهر بشارة «جديد» بدل 0.0.

## الأمان المطبَّق
- **كلمات المرور:** `scrypt` مع ملح عشوائي لكل حساب، ومقارنة بزمن ثابت.
- **أكواد التفعيل:** عشوائية قوية (60 بت)، تُخزَّن كتجزئة SHA-256 فقط، ومحاولات التخمين محدودة بالمعدل (429).
- **الجلسات:** رمز عشوائي في كوكي `HttpOnly; SameSite=Lax`، يُخزَّن مجزّأً في القاعدة، وتُلغى عند الخروج أو تغيير كلمة المرور.
- **الصلاحيات (على الخادم):** `user` / `owner` / `admin` مفصولة. لا مسار يسمح بإنشاء مسؤول أو تغيير الدور (التسجيل العادي يتجاهل أي `role` مُرسَل). كل استعلام للمالك مقيّد بـ `owner_id` الخاص به (ملعب غيره → 404).
- **منع الحجز المكرر:** مفتاح أساسي فريد `(ملعب، تاريخ، ساعة)` داخل معاملة قاعدة بيانات.
- **أخرى:** حماية CSRF (فحص `Origin` + JSON فقط + SameSite)، رؤوس `CSP` و`X-Frame-Options` و`nosniff`، رفع الصور بفحص النوع الفعلي (magic bytes) وحد للحجم مع أسماء عشوائية، منع الوصول لملفات الخادم وقاعدة البيانات، واستعلامات مهيّأة (Prepared Statements) ضد حقن SQL.

## الترقية من النسخة السابقة
لو عندك قاعدة بيانات من النسخة 2.0 في `server/data/` فلا تحذفها: الخادم يضيف الأعمدة والجداول الجديدة تلقائيًا عند التشغيل ويحافظ على الحسابات والحجوزات (مُختبَر).

## حدود معروفة (غير منفَّذ)
- لا يوجد استرجاع كلمة مرور ولا تأكيد البريد الإلكتروني (يحتاجان خدمة بريد). رسائل «تواصل معنا» تُحفظ في لوحة المسؤول فقط ولا تُرسل بريدًا.
- SQLite مناسبة لخادم واحد وحمل متوسط؛ لعدة خوادم انقل إلى PostgreSQL.
- حدود المحاولات في ذاكرة الخادم (تُصفَّر عند إعادة التشغيل).
- لا يوجد نظام دفع. عناوين ملاعب سوهاج في `server/seed-stadiums.json` أمثلة؛ البذرة تُحمَّل أول مرة فقط، وبعدها عدّلها من لوحة التحكم.
- للإنتاج: شغّله خلف HTTPS (Nginx/Caddy) مع `COOKIE_SECURE=1`.

npm test                       # اختبار الخادم والأمان (100 حالة): أكواد، صلاحيات، عزل المالكين، تزامن، CSRF، رفع الصور، الإغلاقات، الإيقاف، ترحيل قاعدة البيانات القديمة

## بنية الملفات
- `server/server.js` الخادم والـ API · `server/seed-stadiums.json` ملاعب البداية · `server/data/` قاعدة البيانات والصور (يُنشأ تلقائيًا)
- `public/` الواجهة: الصفحات (`index, stadium, booking, my-booking, login, register, profile, contact, about, admin`) + الجديدة (`owner-register, owner-login, owner-dashboard`)
- `public/js/store.js` الاتصال بالـ API · `owner*.js` · `admin.js` · `i18n.js` (عربي/إنجليزي) · `css/` التصميم
- `tests/` اختبارات الخادم والواجهة
